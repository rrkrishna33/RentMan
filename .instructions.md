# RentMan - Agent Instructions

## Project Overview
**App Name:** RentMan
**Developer/Branding:** GellSoft (Premium Software Solutions)
**Type:** Flutter rental management application for general-purpose rental businesses (equipment, furniture, event supplies, etc. — not limited to wedding/event rentals)
**Target:** Android (primary), iOS support

> This project was duplicated from the Mrinaya Rental Hub codebase (wedding rental client)

## Critical Business Logic

### Booking Formula (MUST NOT CHANGE)
```
Total Amount = Rent Amount + Security Deposit
Balance Due = Total Amount - Paid Amount
Status: "Fully Paid" if balanceAmount == 0, else "Balance Pending"
```

**Key Points:**
- Rent Amount and Security Deposit are stored separately
- Total Amount combines both (NOT stored separately)
- Balance Due is computed, NOT stored as a flag
- Status must be dynamic based on actual `balanceAmount`, never use the stored `balancePaid` boolean for display

### Booking Display Hierarchy
1. Rent Amount (calculated as: totalAmount - depositAmount)
2. Security Deposit
3. -------- (Divider)
4. Total Amount (bold, calculated as: totalAmount)
5. -------- (Divider)
6. Paid Amount
7. Balance Due (bold, color-coded)
8. Status badge

This layout appears in:
- [lib/screens/booking_details_sheet.dart](lib/screens/booking_details_sheet.dart) - Bottom sheet when viewing booking
- [lib/services/invoice_service.dart](lib/services/invoice_service.dart) - Generated PDF invoices

## Common Update Patterns

### When Adding/Modifying Booking Amount Display
1. Always show Rent as `totalAmount - depositAmount` (calculated, not stored)
2. Always show Total as `totalAmount`
3. Status must check `balanceAmount == 0`, NOT `balancePaid` boolean
4. Update in both [booking_details_sheet.dart](lib/screens/booking_details_sheet.dart) and [invoice_service.dart](lib/services/invoice_service.dart)

### When Editing an Existing Booking
1. In [add_booking_screen.dart](lib/screens/add_booking_screen.dart) `initState()`:
   ```dart
   final rentAmount = booking != null ? (booking.totalAmount - booking.depositAmount) : 0.0;
   _totalController = TextEditingController(text: booking != null ? rentAmount.toStringAsFixed(0) : '');
   ```
2. Extract rent from total, not from a stored rent field
3. On save: `totalAmount: rentAmount + depositAmount`

### When Adding UI Features
- Use SettingsService for theme colors (AppTheme.primary, AppTheme.success, AppTheme.warning)
- Use ConsumerWidget with Provider if reading/modifying app state
- Use GradientHeader widget for page headers (from [lib/components/app-shell.tsx](lib/components/app-shell.tsx) equivalent in Dart)
- Keep consistent button styling (ElevatedButton for primary, OutlinedButton for secondary)

### When Working with Invoices
- Always pull company info from SettingsService
- Calculate rent as `totalAmount - depositAmount`
- Status must be dynamic: `balanceAmount == 0 ? 'PAID IN FULL' : 'BALANCE PENDING'`
- Use AppTheme colors (green for paid, orange for pending)

## Important Constraints

### DO NOT
- Store rent amount separately in the Booking model (calculate from total - deposit)
- Use the `balancePaid` boolean for display (it's deprecated for UI, only for backward compat in DB)
- Display `depositAmount` in Recent Bookings (show `balanceAmount` instead)
- Remove the "Mark Balance as Paid" button when user edits amount after marking paid
- Hardcode colors - always use AppTheme constants

### DO
- Always recalculate status dynamically based on actual balance
- Use Consumer<BookingProvider> for reactive updates
- Call `notifyListeners()` after any data modification
- Validate amounts > 0 in forms
- Show loading indicators during async operations

## Database Schema Notes
- Bookings table: id, customerId, rentalDate, bookingDate, totalAmount, depositAmount, paidAmount, balancePaid, balancePaidDate, specialNotes, lastUpdated
- Customers table: id, name, phone, address, createdDate
- BookingItems table: id, bookingId, itemName, category, quantity
- Categories stored as comma-separated string in preferences (defaults: Furniture, Equipment, Electronics, Decor, Other)
- `rentalDate` was renamed from `eventDate` in DB version 6 — `_onUpgrade` in [database_helper.dart](lib/database/database_helper.dart) does an `ALTER TABLE ... RENAME COLUMN` for existing installs
